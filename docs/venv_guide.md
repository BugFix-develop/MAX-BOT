# Руководство: Всё про виртуальное окружение (`.venv`) в Python

> **Цель руководства:** Раз и навсегда разобраться, что такое `.venv`, зачем оно нужно, как не путать его с файлом `.env`, и как с ним работать на macOS/Linux.

---

## 1. Главная путаница новичков: `.env` vs `.venv`

Из-за похожих названий их часто путают, но это **совершенно разные вещи**:

| Название | Что это такое | Для чего нужно | Что внутри |
| :--- | :--- | :--- | :--- |
| **`.env`** (файл) | Обычный текстовый файлик на пару строк | Хранение секретов (токены, пароли) | Текст: `MAX_BOT_TOKEN=xyz123` |
| **`.venv`** (папка) | Директория с изолированным Python | Изоляция библиотек проекта | Исполняемые файлы `python`, `pip` и сотни мегабайт библиотек |

---

## 2. Зачем вообще нужен `.venv`?

### Проблема «Глобального Python»
Когда ты покупаешь Mac или ставишь Linux, в системе уже есть системный Python (например, `/usr/bin/python3`).

Представь ситуацию без `.venv`:
* Проект А требует библиотеку `pydantic` версии `1.10`.
* Твой бот (Проект Б) требует `pydantic` версии `2.0+`.
* Если ты ставишь библиотеки глобально через `pip install`, новая версия перезапишет старую, и Проект А перестанет работать!
* На macOS система вообще может запретить ставить что-то глобально (ошибка: `externally-managed-environment`).

### Решение: Виртуальное окружение
`.venv` — это **локальная песочница** внутри твоего проекта.
У проекта появляется свой личный интерпретатор `python` и своя личная папка для библиотек. Всё, что ты ставишь для бота, остаётся только внутри этой папки и никак не влияет на операционную систему или другие проекты.

---

## 3. Что находится внутри папки `.venv`?

Когда создаётся окружение, Python делает копию структуры:

```text
MAX-BOT/
├── .venv/                         # Твоя изолированная среда
│   ├── bin/                       # Исполняемые файлы
│   │   ├── python3                # Локальный интерпретатор Python
│   │   ├── pip                    # Локальный установщик пакетов
│   │   └── activate               # Скрипт включения окружения
│   └── lib/python3.9/site-packages/ # Сюда скачиваются все библиотеки (pydantic, requests, dotenv...)
├── config.py
└── requirements.txt
```

> ⚠️ **Золотое правило:** Папка `.venv` **никогда не коммитится в Git**! Она весит много и привязана к конкретной ОС. Любой другой разработчик (или ты на сервере) просто пересоздаст её одной командой. В файле [.gitignore](file:///Users/danis/MAX-BOT/.gitignore) строчка `.venv/` уже добавлена.

## 4. Пошаговая работа с `.venv` (Шпаргалка команд для macOS)

Открой терминал в папке проекта (`MAX-BOT`) и выполняй шаги по порядку:

### Шаг 1: Создание окружения (делается 1 раз на проект)
```bash
python3 -m venv .venv
```
*Что произошло:* Python создал в корне проекта скрытую папку `.venv`.

---

### Шаг 2: Активация окружения
```bash
source .venv/bin/activate
```
*Что произошло:*
1. В начале строки терминала появится префикс: `(.venv) danis@MacBook:~/MAX-BOT $`.
2. Твоя переменная `$PATH` временно переключилась: теперь команды `python` и `pip` указывают на файлы внутри `.venv/bin/`, а не на системные!

Проверить это можно командой:
```bash
which python
# Выведет: /Users/danis/MAX-BOT/.venv/bin/python
```

---

### Шаг 3: Установка зависимостей проекта
Теперь, когда окружение активно, установи все нужные библиотеки из [requirements.txt](file:///Users/danis/MAX-BOT/requirements.txt):

```bash
pip install -r requirements.txt
```
*Что произошло:* `pip` скачает `pydantic`, `pytest`, `requests`, `python-dotenv` и положит их внутрь `.venv/lib/.../site-packages/`.

---

### Шаг 4: Деактивация (когда закончил работу)
Если ты хочешь выйти из изолированной среды:
```bash
deactivate
```
Префикс `(.venv)` исчезнет, терминал вернется к обычному глобальному Python.

## 5. Как подружить `.venv` с редактором (VS Code / Antigravity / Cursor)

Чтобы редактор понимал установленные библиотеки и не подсвечивал строки `import dotenv` или `import requests` желтым/красным:

1. Нажми комбинацию клавиш: **`Cmd + Shift + P`** (Command Palette).
2. Начни вводить: `Python: Select Interpreter`.
3. Выбери вариант с пометкой **`('.venv': venv)`** или укажи путь `./.venv/bin/python`.
4. Готово! Теперь редактор использует именно этот интерпретатор и видит все установленные пакеты, автодополнение работает на 100%.

## 6. Частые вопросы и мифы

### Q: Нужно ли создавать `.venv` каждый день?
**Нет.** Папка создается один раз. Каждый день при открытии нового окна терминала ты просто делаешь:
```bash
source .venv/bin/activate
```
*(А многие IDE делают это автоматически при открытии встроенного терминала).*

### Q: Что делать, если что-то сломалось или пошло не так?
Виртуальное окружение легко «сжечь и построить заново»:
```bash
rm -rf .venv                      # удаляем старую папку
python3 -m venv .venv             # создаем новую
source .venv/bin/activate         # активируем
pip install -r requirements.txt   # накатываем библиотеки
```
